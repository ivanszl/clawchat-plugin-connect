# Require one Runtime Adapter release standard

Every released and future Runtime Plugin capability must maintain a complete profile against the numbered normative requirements in `docs/runtime-adapters.md` and pass the shared Runtime Adapter conformance suite. The standard fixes Connect semantics for Binding ownership, native discovery, visibility and adoption, Workspace identity, Session execution, turn control, receipts, Activity and history, Interactions, catalogs, Turn Submission, native lifecycle, recovery, compatibility, and release evidence; a native runtime may report a feature as partial or unsupported but may not introduce a runtime-specific substitute above the Runtime Adapter seam. In particular, discovery includes all discoverable top-level native Runtime Threads in the selected ownership scope regardless of which native client created them, while child threads remain below their parent and visible but unsafe threads are not silently omitted or adopted.

Keeping the numbered requirements, required surface checklist, discovery-result contract, capability-profile template, official capability matrix, and deferred verification list in one document makes the Runtime Adapter module deeper: Core and tests depend on one stable Interface, while native protocol differences remain local to each Adapter. Adding a new Agent Runtime therefore updates every surface row and its evidence rather than creating another product-specific definition of Session discovery or lifecycle behavior. Discovery returns completeness and per-thread adoption availability together, so an Adapter cannot express a failed or unsafe observation as an authoritative empty array.
