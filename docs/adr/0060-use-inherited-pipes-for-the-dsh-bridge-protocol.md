# Use inherited pipes for the DSH Bridge protocol

The DeepSeek Harness Runtime Adapter and its exactly paired Integration Bridge communicate over two dedicated anonymous pipes inherited by the Connect-owned DSH process: one Adapter-to-Bridge descriptor and one Bridge-to-Adapter descriptor. DSH stdin/stdout remain untouched, no loopback listener is opened, and possession of the inherited descriptors is the local capability boundary. Frames are size-limited newline JSON with request IDs; unknown fields are ignored only within a compatible protocol major, malformed or oversized frames fail the Binding, and writes honor backpressure.

The first Bridge frame is a capability handshake that names the Connect Bridge protocol/version, Connect build, verified DSH CLI version, resolved versions of critical DSH service packages, canonical Home, selected Profile, session format, and capabilities actually present in that Profile. DSH Web's `host.describe.version` and the SDK's `serverInfo.version` are both hard-coded `0.0.1` in the reviewed release and provide no negotiation, so neither is a compatibility signal. The root CLI version is also insufficient by itself: npm `latest` is root `0.1.0-rc.7`, but its caret prerelease dependencies currently resolve critical services to rc.8. Compatibility therefore requires an explicitly qualified resolved-component fingerprint plus behavioral handshake; mismatches fail before Session adoption.

Acknowledged input includes the stable Connect `inputId` and native `MessageId` only after the inbox splice is observed and `sessions.flush()` completes. Cancellation settles only after the native `turn/end` reason is known. On shutdown the Adapter asks the Bridge to dispose every Agent, the Bridge closes both descriptors, and the Adapter then applies bounded `SIGTERM`/`SIGKILL` supervision. A lost reply is reconciled from native history and is never automatically replayed.

The [published-runtime surface probe](../../.scratch/deepseek-harness-integration/prototype/result-runtime-surfaces.md) verified the inherited-pipe handshake, resolved-component fingerprint, durable receipt, completed/aborted terminal events, catalogs, and orderly descriptor cleanup against the current published install. It also showed that an out-of-tree bare import does not inherit DSH's package resolution. The Runtime Plugin must therefore carry a self-contained, version-pinned Bridge dependency closure without installing it into the selected Profile or bundling duplicate DSH service instances.

## Frame limit and history paging (protocol major 2)

Frames are limited to one shared 16 MiB (`DSH_BRIDGE_MAX_FRAME_BYTES`, announced in `hello.protocol.maxFrameBytes`). The Bridge never throws from `send()` and never exits because an outgoing frame is large: oversized events, ok-responses and interaction requests have their largest strings truncated to a marked preview (inline base64 is omitted), carry a structured `truncated` marker, and, for events only, fall back to a minimal placeholder that preserves the Turn lifecycle fields; an unshrinkable response becomes a `frame-too-large` error response. An oversized incoming line still terminates the Bridge (it guards against garbage) and logs the size first. The Bridge protocol has no paged content fetch for a single event; the full content stays in the DSH Session log.

Connect never needs a whole DSH Session, and the Bridge `history` method cannot return one: it returns the newest matching events within a byte budget (default 4 MiB, ceiling 8 MiB) plus `complete` and, when the budget cut the window, `nextBeforeSeq`. Parameters: `headerOnly`, `lastTurns`, `types`, `beforeSeq`, `limit`, `maxBytes`. Starting a Turn seeds the Activity Projector from the latest Turn plus Turn-less command events (`lastTurns: 1`), which yields the same Activity ids and positions as a full replay (covered by an equivalence test); thread readiness is header-only; `readActivity` is a recent window of five Turns and reports `partial` when anything was left out; input reconciliation searches `user/message` events newest-first for at most eight windows and returns `unknown`, not `absent`, when that did not cover the Session, so a bounded miss can never cause a duplicate Turn. Major 2 refuses a major 1 Bridge or Adapter.
